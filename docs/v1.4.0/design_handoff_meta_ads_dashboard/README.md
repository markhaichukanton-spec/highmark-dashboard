# Handoff: Meta Ads Dashboard (High/Mark · Aurora Scents)

## Что это
Аналитический дашборд эффективности рекламы Meta для клиента (read-only client
view). Один экран: шапка с периодом и сравнением, панель фильтров, 10 KPI-плиток,
интерактивный график «метрика во времени», горизонтальные бары по странам и drill-down таблица
Кампания → Адсет → Объявление.

## Главное про этот пакет
Файлы в `design/` — **рабочий прототип на HTML+React (через Babel в браузере)**.
Это эталон внешнего вида и поведения, **полностью отрисованный и интерактивный**.
Задача — перенести этот дизайн в ваше окружение (React/Vue/SvelteKit/Next и т.п.)
по принятым в вашем проекте паттернам, **или** использовать прототип почти как
есть и подключить данные.

Ключевая особенность: **данные и представление уже разделены.** Весь фронт читает
один объект `DATA`. Поэтому «натянуть на базу» сводится к одному:

> вернуть из API JSON по схеме `DATA_CONTRACT.md` и отдать его во фронт
> через адаптер `data-loader.example.js`. Никакой вёрстки трогать не нужно.

## Уровень детализации
**High-fidelity.** Финальные цвета, типографика, отступы, состояния и
адаптивность. Воспроизводить попиксельно.

## Экраны / блоки

### 1. Шапка (`.dash-head`, компонент `Header`)
- Логотип `High/Mark` (слэш — золотой `#C9A84C`), вертикальный разделитель,
  надзаголовок (eyebrow) + H1 «Performance Overview».
- Справа: пилюля периода (иконка календаря + `from → to`), селект сравнения
  (`vs previous period / year / no comparison`), кнопка `Export`.
- Слим-шапка (`.dash-head`) с периодом/сравнением/Export — ВСЕГДА липкая
  (`position:sticky; top:0`); фильтры+KPI пинятся под ней и бинарно сжимаются при
  скролле; при прокрутке до таблицы блок фильтров+KPI получает класс `away`

### 2. Панель фильтров (`.filter-bar`, компонент `FilterBar`)
- Метка `FILTERS` + 7 мультиселектов (Source, GEO, Campaign Type, Device,
  Campaign, Adset, Ad) + кнопка `Reset (n)`.
- Каждый мультиселект (`MultiSelect`): чекбоксы, поиск, «Select all / Clear».
  Первая опция в списке — псевдо-метка «Все …». Пустой выбор === «все».
- Активный фильтр подсвечивается (золотая рамка + жирный текст сводки).

### 3. KPI-плитки (`.kpi-row`, компоненты `KPIRow` / `KPICard`)
- 10 кликабельных плиток. Клик добавляет/убирает метрику на графике (минимум 1).
- На прокрутке блок KPI **бинарно** сжимается (одноразовый твин с гистерезисом,
  без покадровой привязки к скроллу — иначе дёргается из-за scroll-anchoring);
  названия метрик всегда видны. Слим-шапка с периодом всегда закреплена сверху.
- Внутри: цветная точка-маркер, подпись, дельта-пилюля (зелёная при росте /
  красная при падении со стрелкой), крупное значение (моноширинный), пояснение.
- Выбранная плитка: цветная рамка + верхний акцент-бордер в цвет метрики.

### 4. Гранулярность (`.gran`, компонент `Granularity`)
- Сегмент-контрол `Day / Week / Month / Quarter / Year`. Меняет разбивку ряда
  (на бэкенде — параметр `granularity`).

### 5. График + бары по странам (`.analytics-grid`)
- **MetricChart** (Recharts ComposedChart): бары (Revenue/Spend/Purchases, левая
  ось) + линии (ROAS/CPM/CTR/CR/AOV/CPO/CPC, правая ось). Состав осей и тип
  (бар/линия) задаётся в `METRIC_META`. Подписи значений над каждой точкой,
  кастомный тёмный тултип.
- **GeoBars** (Recharts горизонтальный BarChart): одна полоса на страну,
  отсортированы по убыванию; подпись полосы — значение + доля в %. Переключатель
  Revenue / Spend / Purchases. Потребляет агрегат `geo` (НЕ ряды по дням).

### 6. Таблица (`.table-card`, компоненты `SummaryTable` / `TableRow`)
- Колонки: Campaign/Adset/Ad, ROAS, Purch., Spend, CPO, CR, Revenue, CPC, CPM,
  Clicks, Impr. Сортировка кликом по заголовку (▾/▴), drill-down раскрытие
  (твист-кнопка), 3 уровня вложенности с разным весом/цветом текста.
- Ячейка ROAS красится по порогам: ≥3.0 зелёная, <2.0 красная.
- **Чекбокс выбора на каждой строке (кампания/адсет/объявление):** скоупит график
  на выбранные строки (по уникальному ключу `campaign▸adset▸ad`, самый детальный
  побеждает, без двойного счёта). Выбор НЕ по имени — отметка одного адсета не
  трогает одноимённые в других кампаниях. Таблица показывает все строки; выбранная
  строка + её предки + потомки остаются яркими, прочие затемняются (`tr-dim`).
  Индикатор «N rows on chart» + Clear в шапке. Реализация: `DATA.chartSeriesForKeys(keys)`
  в `dash-data.r2.jsx` (подробности в DATA_CONTRACT.md → «Выбор строк ⇄ график»).
- **Имя всегда целиком + без горизонтального скролла:** `table-layout: auto` —
  числовые колонки сжимаются по содержимому (`width:1%; white-space:nowrap`), а
  колонка имени (без width, `min-width:160px`) забирает остаток. Длинное имя
  **переносится на вторую строку** (`white-space:normal; overflow-wrap:anywhere`),
  никогда не обрезается. Подходит для имён любой длины. ВАЖНО: ячейка имени должна
  оставаться `table-cell` (НЕ `display:flex`); содержимое (твист + имя) inline.
- **Залипающая шапка + свап с KPI:** `<thead>` `position:sticky; top:0`. При
  прокрутке до таблицы блок фильтров+KPI получает класс `away` (уезжает вверх,
  `opacity:0`, `pointer-events:none`), а шапка таблицы закрепляется на его месте
  (см. «Поведение прокрутки» ниже). Чтобы thead физически достигал верха, на
  десктопе у `.table-card` снят `overflow` и задан `min-height: calc(100svh-40px)`.

## Адаптивность (container queries по ширине `.dash`)
Контейнерные брейкпоинты (не вьюпортные) — отвечают на ширину самого дашборда:

| Ширина | KPI | График/бары | Шапка |
|---|---|---|---|
| ≥1024 | 5 в ряд | рядом (4fr / 1fr) | фильтры+KPI липкие, KPI сжимается при скролле |
| ≤1024 | auto-fit (→4) | бары под графиком | заголовок уезжает; фильтры — сетка auto-fit |
| ≤720 | 3 | стек | шапка и фильтры переносятся; длинная подсказка скрыта |
| ≤480 | 2 | стек | компактные отступы, поля на всю ширину |

Важно: как только фильтры переносятся в несколько рядов, шапка перестаёт быть
липкой — иначе высокий блок фильтров перекрывал бы KPI.

## Поведение прокрутки (десктоп, ≥1025) — реализовано в `Dashboard.html`
Вся логика прокрутки — в одном scroll-обработчике + измеритель размеров:

1. **Слим-шапка ВСЕГДА липкая.** `.dash-head` (логотип, период, сравнение,
   Export) — `position:sticky; top:0; z-index:40`. Её высота → `--head-h`.
2. **Липкий бар (фильтры + Key Metrics + Granularity) с СЖАТИЕМ.** `.topbar`
   (`sticky; top:var(--head-h)`) содержит ВСЕ три блока. При прокрутке один раз
   проигрывается твин expanded⇄compact (порог >40 / <12, гистерезис): фильтры
   прячут подписи полей и ужимают паддинги, у Key Metrics скрывается заголовок
   «KEY METRICS» и карточки слегка уплотняются (но сохраняют горизонтальные
   паддинги и читаемый размер значения — не выглядят узкими), Granularity
   ужимается. Всё схлопывается в один аккуратный слим-бар. Высота сжатого бара
   меряется → `--topbar-ch`.
3. **Chart-stage: график ЗАКРЕПЛЁН под сжатым баром (`.overview` sticky).**
   `.overview` — `sticky; top:var(--topbar-ch)`, высота `100svh − topbar-ch`,
   непрозрачный фон. Обёртка `.chart-stage` выше графика на `--stage-room` (≈150px)
   — даёт дистанцию прокрутки, пока график закреплён и полностью кадрирован (НИКОГДА
   не обрезается под баром). 1-й прокрут → бар сжимается, график кадрируется целиком.
   Пока листаешь сквозь stage-room → график держится в кадре. Дальше stage кончается,
   график уезжает ВВЕРХ как обычно, а таблица приходит СНИЗУ (2-й+ прокрут).
4. **Финальный свап: Granularity → шапка таблицы.** Когда таблица доезжает до
   липкого бара, её `<thead>` (sticky `top:var(--kpi-bottom)`) встаёт ровно на
   место строки Granularity — а сам gran-strip схлопывается (`.topbar.swap
   .gran-bar{display:none}`). Фильтры + Key Metrics остаются закреплёнными сверху.
   `--kpi-bottom` берётся ЖИВЫМ из реального низа закреплённого Key Metrics-блока
   в scroll-обработчике (надёжнее, чем мерять заранее). Гистерезис не даёт мигать.
   Только `.dash` ≥1025.

ВАЖНО для реализации: внутри container-query контекста (`.dash` —
`container-type: inline-size`) у `position:sticky` элементов **не применяются
transform/opacity** (браузерный квирк композитинга). Поэтому скрытие бара сделано
через `visibility:hidden`, а сжатие — через inline-стили на layout-свойствах (не
CSS-transition: под непрерывной работой Recharts main-thread-анимация стопорится).
На обычном (не-container) лейауте можно вернуть анимацию transform.

Идея UX: дать выбрать период / фильтры / метрики наверху, а при прокрутке сжать
их в слим-бар и отдать экран графику (закадрировав его целиком), затем —
естественный переход к таблице. При переносе на фреймворк можно сохранить почти
дословно (scroll-хэндлер + измеритель + CSS-переменные + sticky-stage) либо
заменить на `IntersectionObserver` — пороги и поведение описаны выше.

## Состояние (state)
- `selected` — массив выбранных метрик (порядок важен; минимум 1).
- `filters` — `{ [filterKey]: string[] }`; `[]` === «все».
- `gran` — текущая гранулярность.
- `compare` — режим сравнения (источник дельт KPI).
- `compact` — бинарный флаг (сжатие KPI), драйвится прокруткой с гистерезисом;
  анимируется одноразовым rAF-твином через inline-стили.
- Локально в таблице: `sort {key,dir}`, `expanded {path:bool}`.
- В барах по странам: `key` (revenue/spend/purchases).

При живых данных: на изменение `gran`/`filters`/периода — перезапрос
`loadDashboard(...)` (debounce по фильтрам желателен).

## Подключение базы — точка интеграции
Единственная точка — `data-loader.example.js` (`loadDashboard()`), плюс замена
мок-массивов в `dash-data.r2.jsx`. Производные метрики считаются в адаптере,
бэкенд отдаёт только сырые поля. Полностью описано в `DATA_CONTRACT.md` и в
комментариях адаптера.

## Состояния, которые стоит добавить при реализации
В прототипе данные всегда есть. В проде предусмотреть: загрузку (скелетоны
карточек/графика), пустой результат по фильтрам, ошибку запроса, и empty-state
баров (строки с нулевой метрикой уже скрываются автоматически).

## Зависимости прототипа
React 18, Recharts 2.12, Babel standalone (только для прототипа — в вашем сборщике
JSX компилируется заранее). Шрифты — Google Fonts (см. `<link>` в `Dashboard.html`).
