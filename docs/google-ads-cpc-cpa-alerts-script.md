# Google Ads Script — Алерты CPC + CPA через Telegram

Скрипт мониторит CPC и CPA на уровне **групп объявлений** и **групп объектов (Asset Group)** в режиме реального времени (накопительные данные за сегодня). Отправляет структурированные Telegram-алерты в трёх состояниях: **Новый**, **Повтор** и **Решён**. К каждому пакету уведомлений прикладывает полный CSV.

---

## Быстрый старт

1. Открыть **Google Ads → Инструменты → Скрипты**
2. Создать новый скрипт, вставить весь код
3. Отредактировать константы в начале функции `main()`:

```js
const BOT_TOKEN = "...";      // токен Telegram-бота
const CHAT_ID   = "...";      // ID чата или группы (отрицательный для групп)
const THREAD_ID = 631;        // ID топика в супергруппе, или null если не нужен

const THRESH_COST = 50;       // минимальный дневной расход для проверки (валюта аккаунта)
const THRESH_CPC  = 1;        // допустимый средний CPC
const THRESH_CPA  = 1;        // допустимый CPA
```

4. Установить триггер: **каждые 30–60 минут** (обычно раз в час).

---

## Правила срабатывания

Алерт отправляется, если выполняется **хотя бы одно** из условий:

| Условие | Смысл |
|---------|-------|
| `Расход > THRESH_COST` И `средний CPC > THRESH_CPC` | Дорогие клики |
| `Расход > THRESH_COST` И (`CPA > THRESH_CPA` ИЛИ `конверсии = 0`) | Расход без отдачи |

Оба условия требуют превышения порога расхода — это защита от шума на микробюджетах.

`conversions = 0` при любом расходе считается ∞ CPA и всегда триггерит CPA-алерт, независимо от порога.

## Жизненный цикл алерта

```
[Сущность превысила порог]
        │
        ▼
   ┌──────────┐   видим первый раз?   ┌───────────┐
   │ Проверка │ ──────────────────▶   │  NEW 🆕   │ → отправить немедленно
   │ состояния│                       └───────────┘
   └──────────┘   уже активен?
        │
        ▼
   ┌──────────────────┐   lastSentTs > 4ч назад?   ┌──────────────┐
   │ Уже в активных   │ ────────────────────────▶   │ REPEAT ⏱️   │ → повторить
   └──────────────────┘                             └──────────────┘
        │
        ▼  отсутствует в текущем запуске ИЛИ кампания/сущность не ENABLED
   ┌──────────────┐
   │ RESOLVED ✅  │ → отправить один раз, указать причину
   └──────────────┘
```

**Принудительное закрытие:** если `campaign.status ≠ ENABLED` или `entity.status ≠ ENABLED` — алерт закрывается немедленно, независимо от расхода и метрик. Это исключает «призрачные» алерты по приостановленным объектам.

## Управление состоянием

Состояние хранится в **Script Properties** (ключ: `tg_alert_state_<customerId>`) как JSON-объект:

```json
{
  "day": "2026-06-19",
  "active": {
    "Ad Group|123456|789012": {
      "firstSeenTs": 1750300000000,
      "lastSentTs":  1750300000000,
      "lastSeenTs":  1750310000000,
      "meta": { ... }
    }
  }
}
```

- **Ежедневный сброс:** если `state.day ≠ сегодня` — карта `active` полностью очищается. Алерты не переходят на следующий день.
- **Ключ алерта:** `level|campaignId|entityId` — тип триггера (CPC или CPA) в ключ не входит. Переход с CPC-алерта на CPA-алерт не создаёт новый алерт.
- **Защита от переполнения:** если сериализованное состояние превышает 8 000 байт, самые старые записи (по `lastSentTs`) обрезаются — чтобы вписаться в лимит Script Properties 9 КБ.

## Ограничение по времени суток

Скрипт не работает до **08:00 местного времени аккаунта**:

```js
const nowHour = parseInt(Utilities.formatDate(new Date(), tz, "H"), 10);
if (nowHour < 8) { return; }
```

Это предотвращает ложные «нет конверсий» алерты ранним утром, когда дневные данные ещё не накопились.

## Формат сообщения в Telegram

```
💸 Google Ads CPC+CPA ALERTS — 2026-06-19

🆕 2   ⏱️ 1   ✅ 1   (cooldown 4h)

🆕 New issues:
Brand Search → Retargeting
Spend $87.40 | CPC $1.23 | CPA ∞ (0 conv)

Performance Max → Shoes
Spend $120.00 | CPC $1.05

⏱️ Repeated:
Competitors → Generic
Spend $63.00 | CPA $2.10

✅ Resolved:
Brand Search → Retargeting
Resolved
```

- Сущности отсортированы по **расходу по убыванию** внутри каждого раздела.
- Префикс `"Category - "` автоматически обрезается из названий сущностей.
- Сообщения длиннее 4 096 символов разбиваются на последовательные части.

## CSV-вложение

К каждому пакету уведомлений прикладывается файл `google-ads-alerts-sent-YYYY-MM-DD.csv`.

| Колонка | Описание |
|---------|----------|
| `date` | Дата (сегодня) |
| `action` | NEW / REPEAT / RESOLVED |
| `level` | Ad Group / Asset Group |
| `campaign_name`, `campaign_id`, `campaign_status` | Данные кампании |
| `entity_name`, `entity_id`, `entity_status` | Данные группы объявлений / группы объектов |
| `spend`, `avg_cpc`, `avg_cpa` | Форматированы как `$X.XX`; CPA = `∞ (0 conv)` при нулевых конверсиях |
| `cpa_no_conv` | 1 если расход > 0 и конверсии = 0 |
| `trig_cpc`, `trig_cpa` | Какие правила сработали (1/0) |
| `triggered_by` | Читаемое описание триггера |
| `first_seen_ts/local` | Когда алерт зафиксирован впервые |
| `last_sent_ts/local` | Когда последний раз отправлено уведомление |
| `last_seen_ts/local` | Последний запуск, в котором алерт был активен |
| `resolved_at_ts/local` | Время закрытия (только для RESOLVED) |
| `resolved_reason_code` | Машиночитаемая причина закрытия |
| `resolved_reason_text` | Читаемое объяснение причины |

### Коды причины закрытия (`resolved_reason_code`)

| Код | Значение |
|-----|----------|
| `CAMPAIGN_NOT_ENABLED` | Кампания поставлена на паузу или удалена |
| `ENTITY_NOT_ENABLED` | Группа объявлений / группа объектов приостановлена |
| `NO_ACTIVITY_TODAY` | Сущность не вернула ни одной строки для DURING TODAY |
| `SPEND_BELOW_THRESHOLD` | Расход опустился ниже `THRESH_COST` |
| `CPC_NORMALIZED` | CPC вернулся в допустимые рамки |
| `CPA_NORMALIZED` | CPA вернулся в допустимые рамки |
| `CPC_AND_CPA_NORMALIZED` | Оба показателя нормализовались |
| `UNKNOWN` | Условие больше не выполняется, детали недоступны |

## Какие типы сущностей покрывает

| Уровень | Ресурс GAQL | Типы кампаний |
|---------|-------------|---------------|
| Ad Group | `ad_group` | Поиск, КМС, Шопинг, Видео |
| Asset Group | `asset_group` | Performance Max |

Оба запроса выполняются независимо, результаты объединяются перед сравнением с состоянием.

## Ограничения

- **Лимит Script Properties:** 9 КБ на одно свойство. Состояние обрезается автоматически, но в аккаунтах с сотнями одновременных алертов самые старые записи могут теряться.
- **Только данные за TODAY:** все запросы используют `WHERE segments.date DURING TODAY`. Состояние сбрасывается в полночь по часовому поясу аккаунта.
- **Нет исторического тренда:** скрипт сравнивает текущие значения с фиксированными порогами — скользящих средних и базовых линий нет.
- **Reach не включён:** метрика `reach` не является аддитивной и намеренно исключена из алертов.
- **Один аккаунт:** скрипт работает внутри одного аккаунта Google Ads. Для мониторинга на уровне MCC — разворачивать по копии на каждый аккаунт или использовать скрипт Управляющего аккаунта.
